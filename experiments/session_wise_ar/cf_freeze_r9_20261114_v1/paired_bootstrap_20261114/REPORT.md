# CF 四组：用户配对 bootstrap（2026-11-14）

只读统计：使用远端已有的逐样本预测文件，没有训练、推理或改动远端文件。两组之间的差值按用户聚类重采样：被抽中的用户保留其全部样本，估计量为样本均值之差，10000 次，seed 2024，95% 百分位区间。p 为 bootstrap 双侧比例，p=0 表示 <1/10000。Holm 校正只在测试集的 5 个比较之间做。验证集 4733 名用户，测试集 4153 名用户。每个比较都核对了样本 ID 和用户 ID 逐一对齐，组均值与原测试/验证收据完全一致。

## 解释边界

- 测试集上，冻结后的 Mixer 优势和冻结对 Mixer 组的收益都很明确，经过校正后区间仍不含零。R35 是事先固定的最终节点，不是看测试结果挑出来的。
- **但同一 R35 节点在验证集上不支持冻结后的 Mixer 优势**（−0.23%，区间含零）。冻结对 Mixer 组的收益在验证集上也只有 +4.35%，区间含零。CF 在验证和测试之间的差异仍未解释，这是主要保留。R10–R35 的逐轮验证均值支持有 Mixer 冻结组更高（R10–35 均值约 +3.8%，26 轮中 20 轮更高），但那是描述性统计，没有做配对区间。
- 持续联合训练下，Mixer 在 R35 测试和验证上都没有可靠差异。
- 这里的区间只覆盖用户抽样的不确定性，不覆盖训练 seed、选点和冻结时点的不确定性。全部为单 seed（2024）。冻结组与持续组的 T 更新预算不同，有/无 Mixer 两组从 RQ 预训练起就分开训练，所以差异不能只归因于联合阶段的交互。

## 文件

- `bootstrap.py`：协议和远端只读计算；`probe.py`：文件定位；`jexec.py`：缓存的 SSH 隧道失效后，改用 SDK Jupyter 通道执行。
- `RESULTS.json`：完整结果，包括输入文件的远端路径和 SHA256；`BOOTSTRAP_RAW_OUTPUT.txt`：远端原始输出。

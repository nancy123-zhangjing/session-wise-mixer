# Stage07 商品内交互：新增两个训练种子

本轮目标：检查当前商品内交互的收益能否随训练随机性变化而复现。新增 seed 2025、2026，每个 seed 各训练 A（关闭商品内注意力）和 B（开启商品内注意力），共四组。原 seed2024 是已有参考，不重复训练。这里只评估验证集，不评估测试集；保留冻结 Pipeline 构造阶段对数据各split的预处理行为，测试目标不参与优化或选模。

## 起点和模型

- 四组只读复用 Stage05 `refined_joint` 配方锁定的离线 Refined-PSE v2 与匹配的 DiffGRM 权重及13件输入；不使用旧07固定SID的84轮状态，也不使用05共享起点四组短对照的最终权重。
- 每对 A/B 共有参数、初始SID和初始训练RNG必须逐项匹配。B新增的商品内注意力为原1层4头、dropout 0、输出投影零初始化，位置和原实验一致。
- 不改全局 Mixer、训练损失、搜索方法、有效 batch 或引擎。引擎冻结为 `1c879252f6395d6e64462511823c3929b9c42c00`；原训练实现来自根提交 `842ff2aa3b0ba95d0ba2a66dea74c485abaa11a1`。
- `rand_seed` 分别为2025/2026，历史资产路径和 `crosspse_seed=2024` 保持原样。记录跨seed参数/RNG差异。这是相同离线暖启动条件下的训练随机性复验，不是重新预训练Tokenizer和骨干的三次独立全流程实验。
- 代码审阅发现，DIGER路径未使用的遗留 `joint_sequence_adapter` 也随seed初始化，因此跨seed的全基础状态SHA可能不同；不能据此宣称四组所有tensor完全相同。同seed A/B的基础状态仍必须精确一致。

## 训练量和选模

- 5轮推荐器暖身，再循环1个Tokenizer阶段加3轮推荐器，共45逻辑轮，即35轮推荐器和10个Tokenizer阶段。
- 每个Tokenizer阶段96个batch、累积16，合计60次Tokenizer更新；推荐器合计3640次更新；10次SID刷新。每组必须实际达到这些数量。
- 唯一停止策略覆盖是 `patience: 5 -> 0`，保证四组完整训练量一致。原seed2024实际也跑满上述预算；验证最佳权重选择规则不变。故障和时限保护仍生效，不允许为跑满而忽略异常。
- 保留初始验证，以及按推荐器轮数每5轮的验证；用beam32的 `0.8*NDCG@10+0.2*HR@10` 选择首次最大值，包括epoch0。不能要求新seed也选第25轮，不能按beam256另选权重。

## 评估和判断

- 每个新模型严格加载上述best及同一checkpoint保存的SID；只同步映射，不重新量化。对同一验证集分别评估beam32和256。
- beam32必须复现训练选模记录；两个beam保持相同checkpoint、SID、数据和精度。保存逐用户指标、权重及输入哈希和完成收据。
- 汇总三个seed在每个beam的 A、B 指标和配对 B−A，报告各seed、均值和标准差。先判断方向是否一致、收益是否被训练波动淹没。不能将22,363个验证用户当作22,363次独立训练；三seed仍是初步证据。
- 原实验为SID级匹配，保留碰撞限制，不冒称独立商品级收益。若小beam稳定向好、大beam不稳定，只支持有限搜索预算下的收益假设。
- 本轮不增加搜索去重、末位Top5、调参或测试集比较，避免改变正在验证的问题。

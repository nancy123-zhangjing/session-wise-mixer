# 07 同一验证集 beam32 / beam256 对照

搜索宽度确实影响商品内交互的收益幅度：B 相对 A 的 NDCG@10 提升从 **3.27% 降到 1.59%**，HR@10 提升从 **3.56% 降到 1.07%**。宽 beam 下收益仍然存在，但比原先窄 beam 的验证结果小。

## 本次回答什么问题

此前验证用 beam32，测试用 beam256，直接比较两边的提升会混入搜索设置的影响。本次固定07交替联合训练 A（原版）和 B（商品内注意力）各自第25轮最佳权重及对应SID，只改变beam，在同一验证集22,363名用户上评估四个组合。没有重新训练、重新选权重或评估测试集。

四格均为confidence解码、历史长度50、batch8、输出Top-10，沿用原来的SID级指标和候选处理方式。两组beam32的七项指标与原验证记录完全一致。

## 主要结果

| 模型 | beam | HR@10 | NDCG@10 | Top-10重复率 | 平均不重复合法候选数 |
|---|---:|---:|---:|---:|---:|
| A 原版 | 32 | 0.069043 | 0.048332 | 35.54% | 6.446 |
| B 商品内交互 | 32 | 0.071502 | 0.049914 | 36.05% | 6.394 |
| A 原版 | 256 | 0.104011 | 0.060457 | 0.23% | 9.977 |
| B 商品内交互 | 256 | 0.105129 | 0.061417 | 0.21% | 9.979 |

| B 相对 A | beam32 | beam256 |
|---|---:|---:|
| HR@10相对提升 | +3.56% | +1.07% |
| NDCG@10相对提升 | +3.27% | +1.59% |
| HR@10绝对差 | +0.002459 | +0.001118 |
| NDCG@10绝对差 | +0.001582 | +0.000961 |
| Top-10命中净增人数 | +55 | +25 |

绝对差也缩小了，因此不只是宽beam下基线变高、相对提升的分母变大。逐用户配对后，beam32下B新增322人命中、丢失267人；beam256下新增356人、丢失331人。两种设置都有较多用户的预测发生变化，净收益较小。

Top-5命中净增基本保持（+41人到+40人），第6–10名命中人数的净差从+14变为−15。因此，并不是各个排名区间的收益都同样缩小。这是人数分布和配对统计，不能直接解释为同一批商品发生了前移。

## 怎么理解

窄beam下平均只有约6.4个不同的合法候选；原解码器会用重复候选补齐Top-10。宽beam几乎能够给满10个不同候选，两组绝对指标都明显提高。因此，搜索宽度是这轮结果的重要影响因素；商品内交互的收益也确实随之缩小。

这不说明交互是通过减少重复起作用：beam32下B的重复率反而略高。候选覆盖和收益变化同时出现，还不足以证明唯一机制。

也不能说此前验证集与测试集的全部差距都来自beam。统一到beam256后，验证集NDCG@10仍提升1.59%，此前测试集只提升约0.43%。预测目标不同、按验证集选择权重、单种子波动等因素仍然没有被这次实验排除。

这轮支持的判断是：**商品内交互存在小幅正向信号，但之前约3%的验证提升依赖搜索设置，尚不能视为稳定泛化收益。** 后续研究应先固定一致的验证/测试搜索协议，再检验增益能否复现。本轮没有据此追加训练或调参。

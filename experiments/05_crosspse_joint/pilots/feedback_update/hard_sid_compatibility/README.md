# 固定初始 Decoder：硬 SID 兼容性诊断方案

本次已完成，核心结论及下一步见 [RESULTS.md](RESULTS.md)。

这一步只检查：同一个旧推荐器面对两种更新后的正式硬 SID 时，哪些位置、哪些上下文的评分发生变化。**这是兼容性／方向诊断，不是 Tokenizer 内在质量评估，也不是后续研究必须通过的门槛。**

## 1. 为什么做，以及不说明什么

上一轮逐样本对照确认，推荐反馈影响了编码和最终预测，但没有额外净推荐收益。目标变化子集的少量正差异主要来自保留原编码、避免仅重构组的损失，不能等同主动重编码成功。

本诊断固定推荐器，以免把三轮恢复训练产生的全局参数差异混入当前评分。注意：旧 Decoder 原本学习的是初始编码。更新标签后的损失上升可能只是尚未适配；下降也可能来自较容易预测的标签或碰撞带来的粗粒度目标，不能直接推出商品表征更好。

本轮 DIGER 的无噪声训练前向也是精确 hard one-hot，soft 仅提供 ST 反向导数。这里不以“训练用 soft、评估用 hard”作为动机。

## 2. 三组如何控制

| 组别 | 使用的 Tokenizer / SID | 推荐器参数 |
|---|---|---|
| Frozen | 共同初始正式 SID | 共同初始 Encoder、Decoder、embedding、输出层 |
| Cross-Recon | 24 次仅重构等更新后的 `post_tokenizer` 正式 SID | 完全相同的初始推荐器 |
| Cross-Rec | 24 次额外推荐反馈更新后的 `post_tokenizer` 正式 SID | 完全相同的初始推荐器 |

来源为 `feedback_pilot_20261012_2150` 的共同 `initial` 及两更新组的 `post_tokenizer` 快照，不使用 `decoder_3` 的恢复后推荐器来替代共同初始推荐器。

固定模型参数、数据、实际截断历史、样本顺序、精度和 mask 条件；关闭 dropout，不执行梯度、优化器步骤或 SID 刷新。正式 SID 用保存的官方映射，不重新最近邻编码覆盖历史结果。

模型前向精度保持原设置。主诊断将**同一套前向 logits 显式转换为 FP32** 后计算 NLL／平滑 CE，own 和 anchor 都采用这一评分精度；不会因此重新跑不同精度的模型前向或改变权重。原 dtype（本环境 logits 为 BF16）的辅助计算只用于核对原实现，不与显式 FP32 评分混成同一数值口径。

每个样本四个目标 SID 位置**全部 masked**。只计算逐位置预测与损失，不生成 Top-K 列表，不执行合法 SID 过滤／回填，也不用测试集。这一固定条件不是随机／guided 训练 loss 的精确复现。

## 3. 记录与评分

正式规模：train 105,668、val 22,363；短测试规模：train 128、val 16。主比较预先固定为 **Cross-Rec − Cross-Recon**，相对 Frozen 为辅助。

每条样本保存身份与实际历史、正式目标 SID、原始四位置 argmax SID、四位置 NLL、label smoothing=0.2 的 CE、逐位置正确性。`0.2` 来自锁定训练配置层的实际解析：`configs/shared/diff_formal_repo_v6.yaml` 覆盖 common 层的 `0.1`。这是对原设置的准确恢复，不是本轮调整超参数。

记录中的 NLL／CE 是显式 FP32 评分，不称为原 dtype 的 loss 精确重放。相同 logits 在 BF16 与 FP32 下计算 CE／NLL 可能因舍入产生差异，不能将跨评分精度的数值差误判成模型前向或编码变化。

同一套 logits 同时对两套目标标签评分：

- own：当前组正式目标 SID，是该组的硬编码兼容性评分。
- anchor：共同初始目标 SID，只作为同 logits 下的诊断参照，不替代正式标签，也不称为正式推荐指标。

anchor 固定标签后，组间 NLL 差异可定位当前固定条件下历史 SID 上下文引起的评分变化。own−anchor 则只反映同 logits 下的**标签换位评分差异**，不能称为编码质量收益。

配对统计包含逐位置和四位置平均 NLL、平滑 CE、准确率；ΔNLL 为左组减右组，负值表示该固定条件下较低。更低／更高／相同样本数以每条样本四位置平均 NLL 差异判定，绝对差不超过 `1e-6` 算相同；总体均值仍保留原始记录，不把微小差异置零。

## 4. 共享分组和碰撞层

沿用前次配对诊断的定义：两种更新组相对 initial 的正式 SID 变化商品并集，所有组使用同一集合。

1. `target_changed`：目标属于并集，无论历史是否也变化。
2. `history_only`：目标不属于并集，实际截断历史中至少一个商品属于并集。
3. `unchanged`：目标和历史均不涉及并集。

碰撞按完整商品 catalog 的完整 SID tuple 多重性统计。baseline 层按共同初始目标 SID 是否碰撞；union 层按三组任意一组目标 SID 是否碰撞。不能按各组分别挑不同样本后横向比较。

## 5. 必须满足的技术核验

- 同 split 三组样本身份、顺序、数量完全一致，目标和非 padding 历史 ID 都在 catalog 中。
- Frozen 正式 SID 等于 initial；标签与各组官方 SID 匹配，正确性与原始 argmax 一致；四位置分数有限、非负。
- 评分数值核验拆成两条同精度路径：显式 FP32 的 flatten 计算对显式 FP32 的逐位置计算；原 dtype 的逐位置辅助计算对原 `full_mask_diagnostics` 实现。各路径沿用原定容差，不要求不同评分精度彼此数值相同，也不通过放宽容差隐藏口径差异。
- 标签未改变的位置，own 与 anchor NLL／CE 相同；Frozen 两套评分完全相同（容许绝对 `1e-6` 浮点差异）。同 logits 的平滑 CE 标签差应等于 `(1−ε)` 倍 NLL 标签差，其中本轮实际解析的 `ε=0.2`。
- `unchanged` 子集三组预测 SID 必须相同，四位置 NLL／CE／anchor 差异不超过 `1e-6`；报告最大差异，超过即停止分析。
- 即使目标 SID 改变，只要历史上下文未变，在全 masked、固定推荐器条件下，预测和 anchor 分数也应一致。这是防止目标泄漏、参数混用或连续码本意外注入的技术检查。
- 各共享分组与碰撞层按样本数加权回到总体，配对更低／更高／相同计数也回到总体。
- 输入权重、官方 SID 和原证据保持只读；新输出不得覆盖历史结果。

这些是保证这次诊断实现正确的核验，**不是要求研究结论必须表现为 loss 下降**。

## 6. 输出与运行入口

轻量推理证据目录保留 `catalog_ids.json`，以及 `frozen`、`cross_recon`、`cross_rec` 下的 `train.records.jsonl.gz`、`val.records.jsonl.gz`，另由运行入口保存版本、输入 hash、模型不变与完整性收据。不复制模型权重或优化器。

纯标准库分析入口：

```text
python -B scripts/analysis/feedback_hard_compat_analysis.py --input-dir <推理证据目录> --output-dir <新的分析目录> --expected-train 105668 --expected-val 22363 --label-smoothing 0.2
```

短测试使用同一入口，将 expected counts 改为 128／16，评分平滑系数仍按实际配置显式传入 `0.2`。CLI 强制要求 `--label-smoothing`，不得猜测默认值。输出为 `compatibility_summary.json` 和分析 `README.md`；目标目录必须不存在，不覆盖原证据。

首个 smoke 版本 `9b09a4b` 在配置解析保护检查处退出。后续 `_r2`／`_r3` 在不合适的跨评分精度比较保护检查处退出，不能作为完整科研结果。修正为两条同精度核验后，使用独立 `_r4` 目录短测试；保留此前失败材料，不覆盖旧证据。通过与否以 `_r4` 对应收据为准，此处不预写诊断结果或科研结论。

最终执行为独立 `_r5` 正式输出。按用户要求精简流程，不再追加一轮 smoke：在 CPU 验证和已定位的数值核对基础上，直接执行一次只读完整统计，保留运行中的全部参数、样本和评分完整性保护。此前失败 smoke 不称为通过，详见结果报告的版本说明。

## 7. 如何据此决定后续

结合正式标签、anchor、共享变化子集及碰撞层共同解释，不按某一个 loss 的正负决定路线。硬标签损失没有下降，不能单独否定反馈或阻止有／无 Mixer 消融；下降也不能替代推荐指标改善。

后续若主要检验恢复不足，可以预先固定三组相同的更长恢复预算；若主要检验交互模块贡献，需要控制共同初始化、正式编码起点和训练预算的有／无 Mixer 对照。两者都不以本兼容性诊断“必须通过”为前提。新实验另行确定和授权，本方案不自动启动训练。

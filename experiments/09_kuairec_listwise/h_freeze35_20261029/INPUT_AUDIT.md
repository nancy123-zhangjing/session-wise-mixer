## 恢复时最容易出错的地方

1. **H0 文件里也有 Mixer 张量和参数组。** B/C 的8个 Mixer 参数均没有 Adam 动量状态，Mixer 张量在 B 与 C 间未变；这是代码保留了关闭的模块，不代表 H0 启用了交互。必须显式用 `mixer_enabled=False` 构建 H0，不能凭张量存在、分支名最后一个字符或删除参数组来猜。
2. **A 是 recovery 外层格式。** 它有原父绑定、执行绑定和内部状态；在 phase33 保持 T200 是正确冻结状态，却不符合原常规 trainer 对 phase33 的 T280 推算。新恢复入口须保留真实计数并按冻结协议检查，不能修改旧 checkpoint 来迎合旧检查器。
3. **C 的 T optimizer 在 T0 是空状态。** 这不是缺失动量；R optimizer 已有3465步动量。恢复后重放必须保留原始阶段编号和数据次序，完成R20后再停止T。
4. 原 H0 R20 checkpoint 确实未保留。重放能核对日志和商品预测，不能据此声称逐位找回原权重、原动量或原 RNG。原 H0 R20 预测只能作为重放参考，不能替代新 C R20 完整状态。

## C 重放门槛建议：正式运行前锁定

R8、R11、R14、R17、R20 均用同一完整验证集核对：

- 样本ID、索引、用户、标签、源数据、计数、阶段编号与批次顺序100%一致。
- 从真实商品ID独立复算的 NDCG@5 与历史值绝对差 **≤1e−6**。
- 最高分单份五件**有序**列表逐样本完全一致比例 **≥99.9%**；71,657条中至多71条不同。
- 指标差和列表一致性须同时通过；报告实际非零差异，不只写“通过”。

这是重放漂移的工程报警线，不是统计等价界。原训练启用了 deterministic algorithms、关闭TF32、无DDP；每阶段训练种子为 `2024 + 100003 × (phase+1)`，数据次序来自独立 `SeedSequence([2024,7919,phase])`。相同软件、GPU、batch和形状下应优先期待高度复现，仍须记录实际运行环境。现有独立复算最大纯计量差小于6.72e−8，1e−6高于该误差约15倍，同时远小于此前约1e−3的实验效果差。不得看到重放结果后扩大门槛。

此外要逐阶段核对原训练日志：C的前20个阶段共有10,595条更新记录，即10,395次R、200次T。应记录损失各项和梯度范数的最大/平均差，不能只因终点NDCG接近就忽略明显轨迹异常。整数时钟和数据次序不设容差；浮点训练轨迹的报警阈值应在短验收后、正式重放前单独锁定，不用测试集或统计显著性替代这一检查。

若出现越界或明显不可解释的轨迹差，保存当前完整边界、排查并报告；至迟不得越过R20进入冻结续训。不能自动重跑、放宽阈值，或把新 run 默认为旧状态。原节点预测SHA、日志SHA和20个阶段的完整数据顺序SHA已封存在 [INPUT_AUDIT_COVERAGE.json](INPUT_AUDIT_COVERAGE.json)。

# 冻结后的 H1 R32：验证前后时段比较

本次复用已保存的完整验证预测，只做CPU统计，没有训练、模型推理或GPU申请。比较固定为原H0 best R32、原H1 R20、H1在R20冻结Tokenizer后继续训练得到的R32，不重新选轮次。

结论：H1冻结续训R32在后段比自身R20提高14.46%，比原H0 best提高8.77%，两项NDCG@5差值的95%用户配对区间都高于0。这支持继续优化推荐器能够缓解先前观察到的后段劣势。不过前段也改善相近，不能把结果解释成已经专门解决了时间泛化。

## 保持与上次完全相同的分段

边界是2020-08-30 07:57:21.188500（北京时间），即1598745441188500微秒。沿用原算法：验证样本中最早首目标时间与最晚末目标时间的中点；首目标时间小于边界归前段，否则归后段。没有把样本等分，也没有重新挑切点。95个跨过边界的五商品块仍按首目标归前段。

- 前段：38,644条，4,011位用户。
- 后段：33,013条，3,827位用户。
- 两段共有3,105位用户；全验证共71,657条、4,733位用户。

数据、原始预测、summary、模型和既有审计均核SHA；预测逐条核商品标签/样本ID/用户与顺序，并从商品ID重新计算指标。仍为H结构、seed2024、beam32、FP32、单份5商品列表及原多列表聚合规则。@10/20/50是候选聚合指标，并非单份长列表。

## 对“推荐器适应不足”的解释

1. **这个猜想获得了支持。** 固定R20的商品编码后，继续优化推荐器能提高后段表现；因此不能把R20时的后段点估计劣势简单解释为这套编码已无法适应更晚行为。这里验证的是稳定编码和继续推荐器优化的这条训练路径，尚未识别唯一机制。
2. **改善主要表现为整体抬升，还不能说时间衰减被消除了。** 自身R20→冻结R32，前段提高13.84%，后段提高14.46%，幅度相近。后段相对前段的NDCG@5落差从34.25%变成33.90%；原H0的落差是22.72%。这些是不同时间样本组成下的描述性比值，不是单独受控的时间漂移效应。
3. **优势更清楚地体现在首份五商品列表。** 后段对原H0，HR@5提高7.17%、Recall@5提高6.51%，两项区间高于0。聚合NDCG@10/@20/@50分别约+4.86%/+3.15%/+3.18%，但这些区间均跨0；Recall@20/@50点估计略低。不能概括为所有K都有明确提升。
4. **原来的“后段差4.97%”也需要降低结论强度。** 本次对同一旧比较补算区间为[-0.00093916,+0.00017686]，跨0。它是值得追查的线索，原先并未证明存在确定的后段劣势。

两段都参与过完整验证选模，H1 R32也是由该验证集选出；所以本次是事后诊断，后段不是独立留出集。原H0 R32累计T360、H1冻结R32为T200，二者训练路径不同，不能由本表直接归因码本交互。正在运行的C组提供同在R20冻结的H0对照；下一步应优先完成这项既定对照，再判断是否仍有时间段差异，而不是立即增加调参实验。

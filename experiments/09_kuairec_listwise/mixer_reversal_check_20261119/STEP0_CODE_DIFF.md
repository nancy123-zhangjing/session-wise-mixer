## 方法

## 结果一：代码

50 个源文件中有 10 个改动过：2 个 DiffGRM 引擎文件，8 个 `scripts/listwise_diffgrm` 文件。

| 部分 | 改动内容 | 对训练的影响 |
|---|---|---|
| DiffGRM 引擎（20 个文件） | 18 个内容相同（最多只有行尾不同）。Mixer 本身的 `cross_pse.py`、`joint_cross_pse.py` 新增一个“关闭码标签嵌入”的消融开关 | 开关默认开启，v2 没有设置它，前向计算与旧版逐项相同。**无影响** |
| `model.py` | 新增可选的 decoder-prefix 模式、常量缓存和输入检查优化 | v2 使用默认的 history 模式，走原来的计算路径。**无影响** |
| `training.py` | 运行中冻结、可选的固定大小 R 单位、fused AdamW、延迟读取指标 | 冻结逻辑与旧运行脚本相同：R20 之后跳过 T、不刷新 SID、退火时钟按 400 次 T 计（旧脚本也断言总数为 400）。fused AdamW 和指标读取只影响数值舍入 |
| `run.py` | 张量缓存和预取、L5O 评估分支、选点指标 | 每阶段重设随机种子的公式相同，验证前后保存并恢复随机状态，训练样本顺序相同。**评估与选点不同**，见结果二 |
| `data.py` | L5O 数据读取观看比；允许列表内有重复商品 | 只在 L5O 数据上生效 |
| `decoding.py` | beam search 中排除历史商品（屏蔽历史） | 只影响评估 |
| `alignment.py`、`runtime.py` | 消融开关和配置校验 | 无 |
| `analysis.py` | 离线分析 | 无 |
| Mixer 的开启方式 | 旧版先以关闭状态构建，从第 5 阶段起打开；v2 的 H1 从共享暖身之后直接以开启状态构建 | 两轮都从第 5 阶段（第一个 T 阶段）起使用 Mixer，时机相同，只是构建方式不同。设计上等价，但没有逐位验证 |

## 结论

1. **训练算法和 Mixer 代码两轮之间没有实质改动。** 代码这一侧剩下的差别只有三类：
   - **选点规则：** 不是主因。v2 的固定终点 R35 不涉及选点，同样为负；旧划分的 R35 同样为正。
   - **评估时屏蔽历史：** 在旧划分预测上用近似屏蔽重新打分，方向不变；v2 不屏蔽的推理还没做（需要改代码）。
   - **数值层面的执行优化：** fused AdamW、微批大小只改变舍入。不太可能在三个 seed 上造成一致的方向翻转，但没有逐位验证。
2. **因此“代码”这个候选可以大幅降级，主要怀疑对象转向数据。** 数据的差别也不止原先说的“测试同期数据”和“历史 128”，还包括：
   - 列表定义：会话内 10 分钟内看完的 5 个不同商品，对比任意连续 5 条、允许重复、含零播放；
   - 训练规模：约 3.2 倍。
3. **对步骤 1 的影响：** 当前代码仍保留旧划分的评估路径（不屏蔽、按曝光 NDCG 选点）。所以“用当前代码在旧划分上重跑三 seed 冻结对照”只需要写配置，不需要新的数据适配和评估代码。
   - 它检验的是“当前训练代码＋执行优化＋运行中冻结”能否重现旧增益。
   - 按本步骤的结果，预期会重现。如果不重现，说明数值层面的差别也能翻转结论，这本身就很重要。
   - 正式运行前需要先在 CPU 上核对配置，再做 GPU 冒烟。
4. **新的待验证列表（数据一侧）：** 划分方式（测试同期数据）、列表定义、历史长度、训练规模。要逐项分开，需要构造数据变体，工作量较大，建议在步骤 1 之后再定。

# 实验代码版本管理

用户于 2026-11-13 明确要求：每次推进一个代码任务后及时提交，按实际任务分批归档。

## 每次修改的流程

1. 查看当前分支、暂存区和工作区，识别其他并行任务的修改。
2. 完成一个明确任务后，提交对应代码、配置、相关测试和必要说明。使用明确文件清单，混合修改按内容拆分。
3. 提交信息说明具体行为；记录已做检查，不把旧检查写成新检查，不因归档重跑实验。
4. 给用户返回 commit 短哈希、改变内容及尚未提交的部分。不默认推送远端。

## 版本边界

- 模型改动、运行效率优化、诊断脚本、结果归档分别提交。
- 完成一次可复现改动就提交，不等整个研究方向完成。
- 训练前保存代码版本；实验清单同时记录代码版本、配置、父 checkpoint 和数据标识。
- 同一文件含不同任务时，先检查能否独立拆分；无法准确重建的旧中间状态不伪造。
- 源码提交不等于训练验收，也不等于数据备份或远端推送。

## 不进入 Git 的内容

模型权重、数据集、大型逐样本预测、打包下载文件、临时日志、凭据和私人草稿保留在原位置。忽略文件不代表删除文件，也不代表远端副本已核验。报告及小型路径/SHA 清单可进入 Git。

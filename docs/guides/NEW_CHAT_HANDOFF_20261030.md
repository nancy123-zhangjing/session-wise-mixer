## 2. 当前模型、数据、分组与指标

### 数据与模型

- KuaiRec 2.0，目录10,728件商品；训练/验证/测试为709,443 / 71,657 / 53,194条五商品列表。验证4,733用户，测试4,153用户。
- 按30分钟间隔构造人工会话，再切五条块；目标五件互异、有正播放，跨度≤600秒，历史5–50件。它是消费续接任务，不是真实曝光请求列表；没有“五件总播放必须60秒”的筛选。
- 使用既定全局时间划分。静态商品文本离线可用是协议假设，不是历史时点内容快照证明；未使用验证/测试行为拟合热门类别。
- 冻结BGE-M3内容编码器；PCA/OPQ及残差PSE预处理固定。PSE四套码本，每套256个64维中心；商品得到四个SID。推荐器的SID embedding是另一套256维参数，不要与内容码本混称。
- 推荐器骨干1层Encoder、4层Decoder、hidden256、FFN1024。四层Decoder不对应四个码位。

| 名称 | 含义 |
|---|---|
| J0 / J1 | 五件商品的20个码位共同去噪；全局Full Mixer关/开 |
| H0 / H1 | 外层依次生成五件商品，每件内部四码DiffGRM；全局Full Mixer关/开 |
| Full Mixer | 全局码本之间的交互；不是07商品内注意力，也不是每个session动态生成一套新商品ID |
| R | 推荐器完整epoch；更新其SID embedding、Encoder、Decoder，固定Tokenizer |
| T | Tokenizer优化器更新次数；更新基础码本及启用的Mixer，固定推荐器。**T200不是200个epoch** |

原四组都联合训练，H0/J0并非冻结Tokenizer。共同起点为同架构 **R5/T0**；随后10次“40T更新＋3R”，共35R/T400。每R为693次更新，35R合计24,255次。训练BF16、microbatch256×累积4；评估FP32、关闭TF32、beam32。实际设置以S1和运行绑定为准，不以初始`base.json`默认微批量为准。

### 三轮实验名称不要混用

1. **原四组**：J0/J1/H0/H1，原H1 best为R20/T200，旧H0 best为R32/T360。
2. **H1恢复至R26**：同一个H1 R20完整状态分为Decay与Freeze。Decay同时降低基础码本和Mixer学习率，并继续T更新；Freeze固定基础码本、Mixer、商品→SID，只继续R。Decay不是“降低更新频率”，也不是仅降低Mixer学习率。
3. **冻结延长至R35**：

| 分支 | 起点与干预 | 固定终点 |
|---|---|---|
| A | H1在R20冻结；本次从已验Freeze R26继续R | R35/T200 |
| B | 从旧H0 best R32开始冻结，再继续R | R35/T360 |
| C | 原H0 R5/T0完整状态重放到R20/T200，通过关口后冻结，再继续R | R35/T200 |

Freeze保留已学到的Mixer，不是把H1变成H0。C不是关闭H1的Mixer，也不是从H0 R32倒推R20；重放R20的71,657条Top5与原记录全部相同，NDCG差0，但不声称逐字节找回了缺失旧权重。

### 评价与统计口径

- 主指标：最高分单份五件列表的真实商品级NDCG@5。HR@5是列表至少命中一件；逐目标命中率的分母则是该类目标出现次数。二者不同。
- 五件目标按相关商品集合计分，不要求预测顺序复现消费顺序。按既定规则消解SID碰撞、列表去重及PAD，不把整个碰撞桶都算命中。
- 聚合@10/20/50由最多32份候选五件列表按原规则展开、去重；**不是一次生成50件**，实际候选可不足50。
- 原四组在R5、8、11…35按完整验证NDCG@5选best；A/C共同候选为R20、23、26、29、32、35，平局选较早。A best=R32，C best=R23；B仅并列父R32与固定R35。
- 用户聚类配对bootstrap：原四组10,000次；恢复/延长及时间诊断按各自协议2,000次。主估计样本均值；不要混为用户等权均值。
- 单seed2024；用户置信区间不覆盖训练seed、选模和事后选冻结点的不确定性。正点估计不自动意味着统计明确改善。

## 4. 时间泛化：冷启动与热门偏置的最新解释

这部分全部使用保存的**validation预测**做CPU离线统计，没有新训练、推理或数据划分。初版旧H0 best、旧H1 R20、冻结H1 R32，之后已补C固定R32和C best R23，共五个不同模型。

切点沿用1598745441188500微秒，即北京时间2020-08-30 07:57:21.188500；以首个目标时间判断，严格小于为前段。前/后38,644 / 33,013条，95个跨界块仍归前段。不得重新选时间点。

### 分类标准与分母

- **严格训练未见（never_seen）**：保留训练样本的历史和目标均未出现，1,914件；静态内容可能已知。
- **仅历史出现（history_only）**：历史出现、从未作目标，799件；不等于参数从未收到梯度。
- **暖商品（target_seen）**：曾作训练目标，8,015件。前两类合称“未作训练目标”，不能全叫严格冷启动。
- 暖商品按训练目标出现次数降序、内部ID升序排序：前802件为热门head，随后3,206件为中频mid，其余4,007件为长尾tail。零目标频次商品保留前两类，不混成长尾。热度不是按推荐次数或未来数据定义。
- Ground truth分布＝用户实际消费的五件目标属于哪些类别；推荐分布＝模型最终输出的位置属于哪些类别。两边都已统计，不能用推荐占比代替命中率。
- 推荐占比按出现位置计数，排除PAD；同一商品在不同样本推荐会重复计数。逐目标命中率按该类目标出现次数作分母；DCG按命中名次折扣归属目标类别，NDCG贡献沿用原五目标IDCG，可相加回整体。

## 5. 当前问题：老师的收敛不一致与one-epoch overfitting

### 已有事实

1. 原T学习率固定（码本1e−5、Mixer1e−4）；R采用35R余弦衰减，后期R步长明显变小。Gumbel幅度1→0.2是噪声退火，不是T学习率退火。
2. Decay两个T块结束、R尚未继续训练时，同一8192诊断子集NDCG@5立即下降10.19%、18.42%；当时不同SID数9600→9630→9643，未发生R35那种大面积碰撞塌缩。子集不可冒充全量验证。
3. 固定编码后继续R，全量验证与测试改善，见第3节。原H1 R20→R35不同SID从9600降至2551，碰撞商品12.91%→91.41%，四槽码字使用181/137/190/218→8/17/15/13，说明末期还存在表示区分能力退化。
4. 原日志有训练loss，但首次完整验证在R5，没有第一遍→第二遍边界的密集验证曲线，也没有与训练目标完全一致的验证loss曲线。原T边界的部分SID/熵诊断返回值未持久记录，不能假称完整历史曲线已存在。

### 推测，尚未证实

- **适应节奏失衡**：编码仍改变商品编号，推荐器后期更新变弱，来不及适应。现有T后掉分和冻结恢复支持继续检查，但学习率差异不是收敛速度的直接测量。
- **表示过拟合**：编码侧开始记训练样本，下游仍需学习；这是CTR文献的相关解释，尚未在本项目确认。
- **其他竞争解释**：T多目标梯度冲突、Mixer修正过大、训练随机选码与确定性推理不一致等。已有anchor/balance和Gumbel退火，不能写成完全没有约束。
- **one-epoch overfitting**严格指第一遍学数据时改善、第二遍刚开始明显掉分，不是所有R20以后退化的统称；本项目尚无足够证据使用该诊断。

冻结有效不等于Tokenizer已经收敛，也不能直接证明“编码器比推荐器收敛快”。编码更新后的暂时不适应与最终SID塌缩应分开分析。数据时间轴的泛化衰减，也不同于训练epoch轴的后期退化。

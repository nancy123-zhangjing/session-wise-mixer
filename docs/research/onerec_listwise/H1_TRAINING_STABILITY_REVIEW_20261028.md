### 1.1 新发现：后期存在真实的码字使用塌缩

四组完整模型已下载、SHA核验并在独立目录恢复。读取全部best/last，再用恢复的有效码本做CPU FP32最近中心选码及独立FP64直接平方距离选码，8个checkpoint均与保存SID完全一致；Python Counter也复核了碰撞统计。这不是只看验证曲线推断，也不是SID缓存未刷新造成的表象。

| 模型状态 | 不同SID组合数 | 处于碰撞桶的商品比例 | 四个码位分别使用的码字数 | 交互修正/基础码本整体范数 |
|---|---:|---:|---|---:|
| H0 R32 best | 9,513 | 14.02% | 256 / 256 / 256 / 256 | 0 |
| H0 R35 last | 9,513 | 14.01% | 256 / 256 / 256 / 256 | 0 |
| H1 R20 best | 9,600 | 12.91% | 181 / 137 / 190 / 218 | 0.824 |
| H1 R35 last | 2,551 | 91.41% | 8 / 17 / 15 / 13 | 4.230 |

目录为10,728件真实商品，PAD不计入。“碰撞商品比例”是落入非单例SID桶的商品占比，不是重复行比例；91.41%也不等于这些商品绝对无法推荐。解码器仍按固定规则对桶内商品消歧，但SID对商品的区分能力明显退化。

H1从R20到R35，每件商品至少有一个码位改变，整体码位变化率91.43%。同期基础码本相对E0的整体位移仅从1.68%增至2.24%，而交互修正的范数大幅增加；说明检查重点应落在Mixer引入的有效编码变化上。不能把整体范数比解释为每个中心都放大4.23倍，也不能据此单独证明是学习率、损失冲突或某一种梯度导致。

J1的R35更严重：全目录只剩1种SID、四槽各用1个码字；其best为共同R5暖身，0次T更新。两个交互版都出现退化，而无交互版基本稳定，支持优先审查共同的交互优化机制；仍不是跨seed复现。

依据：[8个角色SID诊断](../../../experiments/09_kuairec_listwise/formal_execution_20261027/CHECKPOINT_SID_DIAGNOSTICS_20261028.json)、[实际码本与独立距离复核](../../../experiments/09_kuairec_listwise/formal_execution_20261027/CHECKPOINT_GEOMETRY_CHECK_20261028.json)。后者SHA为`93f08350f6584e26e9989691f186e333f2fae6ece5871360e072bd0915df14c0`。这些是端点证据，不能定位塌缩最早出现在哪一次T更新。

## 2. 实际运行设置与可疑点

检查对象是冻结源码1c423662d9a25a926328ee6466c30c0f2857b4f6及恢复目录中的DiffGRM引擎，不用配置默认值代替实际设置。实际配置：[runtime_efficiency_r2.json](../../../experiments/09_kuairec_listwise/preparation_20261027/runtime_efficiency_r2.json)。

| 项目 | 实际设置 | 解释 |
|---|---|---|
| R阶段 | 更新推荐器，固定Tokenizer；AdamW，初始1e-3、500步warmup、全35R余弦衰减 | R20结束约4.03e-4，R26约1.61e-4，R32约1.88e-5，R35为0 |
| T阶段 | 固定推荐器；基础码本1e-5、Mixer1e-4；没有T学习率调度 | 后期仍以相同名义步长更新编码。LR比值不等于实际参数或有效码本位移比值 |
| 交替节奏 | 5R共同暖身后，10次“40次T更新＋3R” | 每个T块后刷新全目录硬SID；应检查刷新幅度及后续R能否适应 |
| Mixer | 全局Full attention、4头、零输出初始化；残差系数1且固定 | 有效码本=基础码本＋交互残差。端点实测H1修正/基础整体范数比由R20的0.824升至R35的4.230，伴随选码塌缩 |
| T损失 | 推荐/重构/均衡/锚定权重1/1/0.01/0.01；SIA=0 | 重构是256维平方误差求和后按商品平均，anchor是元素均值；系数不能直接代表梯度贡献 |
| anchor | 交互后的有效码本与初始码本E0的均方差 | 已有约束，但不是商品分配概率或相邻T块SID变化约束 |
| DIGER-ST | assignment温度0.1；softmax温度固定1；Gumbel幅度1→0.2，400T余弦 | T的hard-forward来自带噪logits的argmax，噪声会改变实际选码；R与推理使用确定性刷新SID |
| 梯度裁剪 | R/T各自全局norm≤1 | 有有限梯度并不保证多目标梯度方向合适 |

代码证据在恢复目录的 `code/scripts/listwise_diffgrm/training.py`（优化器、phase_mode、objective、checkpoint）与 `code/external/DiffGRM/genrec/models/DIFF_GRM/joint_cross_pse.py`（diger_assignments、tokenizer_objective、refresh_hard_codes）。

已经确认后期编码变化和码字使用塌缩；“固定T学习率＋衰减R学习率使推荐器跟不上”仍是待验证的原因，不能直接从端点推出因果。还需区分多目标梯度冲突、随机/确定选码不一致等机制。H1在R32聚合候选覆盖@50约50.92%，高于H0的38.83%；候选数量多不能替代SID区分能力或排序质量。

### 当前日志的证据缺口

`refresh_hard_codes()`已经返回逐码/逐商品SID变化率、唯一码字数、碰撞率；但正式`run.py`只调用`trainer.refresh_catalog()`，没有把返回值写入日志。T阶段也丢弃`diger_assignments()`返回的熵和最大概率诊断。因此不能声称这些历史变化曲线已经存在。

完整checkpoint保存了模型、alignment、两套优化器、scheduler、RNG和进度；保留的best/last可补CPU端点诊断，但不能据此还原每个历史T边界。后续新实验应记录诊断；本轮运行中不改代码。

## 3. 文献依据与迁移边界

### 第一优先：后期固定编码，再让推荐器收敛

[ETEGRec，SIGIR 2025，§3.4](https://arxiv.org/html/2409.05546v3#S3.SS4)明确采用交替优化，并在Tokenizer收敛后永久固定Tokenizer，继续训练推荐器。§4.1.5考察周期长度2或4，即1个Tokenizer epoch与剩余推荐器epoch。

对本项目的启示是：交替联合训练不必持续到最后。可以保留已经学到的Mixer和SID，后期只训练推荐器。论文用不同Tokenizer/对齐损失，不能照搬其epoch比例或声称R20已经收敛。

### 第二优先：控制Tokenizer更新强度和频率

[BLOGER，SIGIR 2026，§4.4](https://arxiv.org/html/2510.21242v2#S4.SS4)研究Tokenizer更新频率与损失权重；其元学习设置中，过密的Tokenizer更新使推荐器适应不足，产生不可靠的元梯度。§4.3也表明，梯度处理在其双层优化中有帮助，但直接加入普通联合训练并未明显提升。

对本项目可先测降低Mixer学习率、减少T更新或增加固定SID下的R适应阶段，每次只改一项。当前没有元梯度，论文的频率最优值与因果解释不能直接套用；也不宜第一步就加入双层优化或梯度手术。

### 第三优先：限制无必要的SID漂移

[DACT，2026预印本，§3.1.3](https://arxiv.org/html/2603.29705v1#S3.SS1.SSS3)用前后阶段商品码字分配概率的KL约束稳定性，原文只对RQ第一层使用，其他层配合分层重分配。

这是持续学习/新数据环境，本项目是固定数据下的优化变化。若确实测到晚期SID大幅漂移，可借鉴“限制相邻阶段分配变化”的原则；本项目PSE四个槽不等于RQ由粗到细四层，不能照搬只约束第一槽。参考分布应固定并detach，比较时使用一致温度和确定性前向。

### 条件候选：噪声退火与码字使用

[DIGER，§4.2、§8](https://arxiv.org/html/2601.19711v1)讨论随机训练选码与确定性推理不一致，提出减小噪声幅度或频率。当前已有幅度退火，不能再次笼统提出“加一个退火”；应先测相同商品的随机/确定性选码一致率，以及码本使用熵、有效码字数与碰撞率，再判断是否需要更早/更充分退火。过早移除探索也可能使码字利用变差。

来源可靠性补充：[DIGER作者仓库](https://github.com/junchen-fu/DIGER)目前说明，历史main复现路径误截断了推荐损失到RQ-VAE的梯度，新实验应看gradient-fix。这里参考其方法假设，不把旧main结果当作正确端到端梯度的无条件证据。本项目使用自有已验收梯度路径，不能据此外推本轮也有同一错误，更不能运行中替换依赖。

## 4. 建议的最小后续诊断：同一个H1 R20状态分三支

问题：**控制或停止后期编码更新，能否避免已观察到的码字使用塌缩，并保住H1的推荐收益？**

完整H1 R20 checkpoint现已验收、本地备份并通过CPU模型前向恢复，best SHA为`a672ea4d31be5281c2c24c1c7e774bc27eb7e679ec732181a197b703da890bf1`。以下仍是未实施的后续分支，不属于原Goal自动追加实验。

| 分支 | R20之后唯一干预 | 能回答什么 |
|---|---|---|
| A | 原设置继续 | 控制轨迹；原R23/R26结果只有在恢复与协议一致性确认后才可复用，否则跑同预算控制 |
| B | 仅Mixer LR从1e-4降到3e-5 | 减弱后期Mixer更新能否缓解退化；3e-5是诊断候选，不是论文给出的最优值 |
| C | 固定基础码本、Mixer与SID，只更新推荐器 | 保留学到的交互表示，让推荐器在稳定编码上继续适应，检验继续T更新是否有害 |

各支再训练相同6R，到R26；在R23、R26用同一完整验证、beam32、相同指标。A/B的T计数200→280；C保持200，这是有意干预，不算等T预算。

保留原优化器状态、R的35R调度及阶段编号；B保留400T噪声时钟，恢复优化器后只覆盖Mixer组LR。C跳过T时不能压缩原R阶段编号，确保R批次索引、阶段重设随机种子仍对应原阶段，避免跳过T导致随机流/批次变化混入结果。仅设同一个初始seed不够。

当前恢复入口强校验配置/源码/更新时钟；后续需要显式的新实验分叉记录与验收，不能伪改绑定绕过校验，也不能覆盖正在运行的源目录。记录冻结分支T时钟不再递增的语义。

主判据预先固定为R26验证单列表NDCG@5相对A的变化，R23用于观察轨迹；同时记录每个T块后的唯一码字/SID数、碰撞率、逐槽熵、有效码本位移及交互范数，检查质量改善是否伴随编码稳定。辅看HR/Recall@5和聚合NDCG@50。不再事后挑一个最好点作为唯一结论。可做用户配对区间，但单seed和基于本轮观察选R20都只能提供诊断证据。

- B较A改善：支持后期Mixer更新强度值得调整；不证明所有R/T失配机制。
- C较A改善：支持固定学到的编码有益；不能区分是Mixer、基础码本更新还是T随机选码造成。
- 两者都改善：优先研究交替学习后转固定编码的训练日程，再判断能否稳定超过原峰值。
- 两者都不改善：不要继续假定只差学习率，应检查过拟合、表示/目标冲突及模型结构。

如果只能加一支，优先C：它最直接地检验“停止继续改编码能否止跌”。这不等于关闭Mixer或从头固定SID。

“止跌”“超过原H1峰值”“稳定超过H0”是三个不同目标。要宣称最后一个，需给H0相当的训练设置优化机会，再在额外seed与统一测试上确认。

## 5. 补充诊断与下一层优化

后续分支优先记录：每次T前后有效码本相对位移、交互残差/基础码本范数比；逐槽及整商品SID变化率；唯一码字数/碰撞率/码本使用熵；随机与确定性选码一致率；分损失对Mixer的梯度范数与余弦；裁剪触发情况。

当前漂移与塌缩已确认，先选更小/衰减的Mixer学习率或后期固定编码。若仍不稳定，再考虑有效码本位移/分配稳定性约束，并核对现有soft balance是否真的约束了hard argmin码字利用。当前已有anchor与balance，不能写成“没有正则”；应记录加权分项梯度和hard利用率，不依据0.01这个系数判断其一定足够或不足。若SID稳定但验证继续下降，再检查过拟合及推荐目标冲突。

不建议同时修改学习率、损失权重、噪声、交互门控和T/R比例。将残差系数从1直接改为0.1会立刻改变有效码本、SID和模型函数，不是等价于降低学习率；若研究该项，应独立对照。

早停/保存best可以避免交付退化的末轮模型，但当前已按验证保存best；早停本身不能解释退化或证明H1可达到更高峰值。

本备忘不授权新增GPU任务。原四组统一测试、恢复和日志验收已完成；本方案仍需作为新的诊断实验单独确定预算，不能在已完成的原Goal内自动追加。

# KuaiRec：两种列表生成方式与码本交互对照方案

日期：2026-10-27。本文保留设计依据；用户后续已授权代码实现，当前实现和验收入口见[代码说明](IMPLEMENTATION.md)、[具体配置来源](IMPLEMENTATION_REFERENCES.md)。本文件保留原始设计；用户后续已启动09执行Goal，真实准备和两份暖身已完成，四分支正式训练正在运行。当前进度、资源调整及验收以[执行记录](../../../experiments/09_kuairec_listwise/EXECUTION.md)为准。

## 1. 本轮要回答的问题

在已锁定的KuaiRec五商品消费续接任务中，沿用PSE、DiffGRM和交替联合训练后，05中的全局Full Mixer是否改善真实商品级推荐质量？这种收益是否依赖列表的生成方式？

| 组 | 列表生成方式 | 全局Full Mixer | 码本是否联合训练 |
|---|---|---|---|
| J0 | 整列表20码联合去噪 | 关 | 是 |
| J1 | 同J0 | 开 | 是 |
| H0 | 外层逐商品、内层四码DiffGRM | 关 | 是 |
| H1 | 同H0 | 开 | 是 |

主要比较是J1−J0与H1−H0。J/H之间属于整套列表建模路线的比较，并非只改变某一个注意力层。关闭Mixer的组也必须更新码本，不能用冻结Tokenizer作对照。07商品内注意力、08历史侧残差、grid/loop均不加入首轮。

这里的Full Mixer仍对全局码本做交互，每个商品在确定性编码时仍有全局SID。session-wise体现为五件目标的联合建模，不表示每个session动态产生另一套商品ID。四组不能直接证明“session-wise比item-wise更适合交互”；该主张需要以后在同一KuaiRec数据和监督预算下补独立商品对照，旧Beauty实验不能替代。

## 3. 共用数据、商品表示和起点

使用`outputs/kuairec_listwise_v1/run1/`及其manifest，不重划分：训练709443、验证71657、测试53194条五件列表。历史5–50件，五件目标互异，列表跨度≤600秒；无总播放60秒硬筛选。完整目录10728商品，保留冷启动和文本缺失。[数据验收报告](kuairec_preparation/REPORT.md)

商品编码建议固定为：

```text
现有静态中文/多语言文本
  → 冻结BGE-M3 dense encoder（1024维）
  → 同一PCA降到256维并按旧流程归一化
  → 原OPQ4,IVF1,PQ4x8流程
  → 四个64维内容槽，各查询256个中心
  → 每件商品4个SID索引
```

选择BGE-M3是适配中文内容的共同预处理设置，不是本轮实验变量；版本、文本模板、长度截断和文件哈希需先锁定。其官方模型卡给出多语言与1024维dense表示，不能继续默认沿用仅因历史Beauty使用过的英文内容配置。[官方模型卡](https://huggingface.co/BAAI/bge-m3)

拟合范围建议沿用已接受的“全静态目录离线可用”假设：PCA和离线PSE可使用10728件商品的静态内容，**不使用验证/测试行为反馈**。四组共享同一次拟合的PCA、OPQ旋转、IVF1粗中心、初始码本E0和SID0；这些内容变换在联合阶段冻结。训练未见商品仍指行为训练未见，不因使用其静态内容就改标为已见。若将来研究严格时间冷启动，另设只用训练可见目录拟合的协议，不混入当前四格。

保留原FAISS的IVF1残差语义，不能改成对旋转向量直接做普通PQ却称同一PSE。缺文本4件保留既有空文本与标记，纳入碰撞审计，不编造商品描述。不使用Beauty的PCA、码本、SID或已训练推荐器权重。

共同初始化：所有可共用参数按相同seed、相同逐参数初始化规则产生。Full Mixer以E0为base及anchor，full attention、4 heads、dropout0、残差系数固定1，输出投影清零，保证初始有效码本等于E0。**J0/J1初始输出须一致，H0/H1初始输出须一致；不同架构不要求输出一致。**

## 4. 两种模型怎样生成列表

### J：整列表联合去噪

历史SID为`[B,50,4]`，各商品的四个256维SID embedding经原item_mlp汇成一个256维向量，历史Encoder输入为`[B,50,256]`。

目标为`[B,5,4]`，Decoder展开为`[B,20,256]`。必须保留`n_digit=4`，另设`list_length=5`和`target_len=20`；展平位置p对应的码位是`p % 4`，商品位置是`p // 4`。四套码表、mask embedding和输出头在五个商品间共享，不扩成20套。

新增五个商品位置embedding，否则全MASK时五件商品的相同码位完全对称。原Decoder没有目标位置编码，不能只改shape。每个目标码位使用“原码位SID/mask向量＋商品位置向量”；Decoder保持双向去噪自注意力，交叉注意原历史。

```text
历史H → Encoder → H_encoded
                    ↓ cross-attention
[物品1四码 | 物品2四码 | … | 物品5四码]
                    ↓ 共同去噪，20位间可交互
             一份五商品列表
```

训练未遮盖的真实目标码只在去噪输入中出现，不进入历史Encoder。推理从20个MASK出发，不能携带真实目标。首轮保留CPD每步确定一个码位的原则，共20个逻辑填码阶段；不自动改成一步生成或一次填五码。

### H：外层逐商品，内层四码DiffGRM

第j件使用条件`H + 前j−1件`，调用同一个四码DiffGRM。训练使用真实已知前缀，推理只能使用模型已生成前缀，不等待用户新的观看反馈。

```text
H                         → DiffGRM四码 → 商品1
H + 商品1                 → DiffGRM四码 → 商品2
H + 商品1 + 商品2         → DiffGRM四码 → 商品3
…
H + 商品1 + … + 商品4     → DiffGRM四码 → 商品5
```

五个子任务共享所有推荐器参数。训练可以展成`B×5`个条件样本并行，但按B条列表归一化，并且每个列表批次只算一次优化器更新。第j个子任务绝不能看当前及后续真实商品。

为保留全部原始50条历史，Encoder位置容量扩到54，前缀占额外4个位置；不把追加前缀后的序列再截回50。J/H共用同形状54位置表与五个目标位置embedding，J不使用历史表的后4个位置。原Encoder是双向的，增加前缀后须重算编码和cross-KV；每件商品内四码解码可复用该条件的缓存。

H逻辑上也是5×4=20个填码阶段。J每次处理20位，H每次处理4位但需更新前缀条件，不能仅凭阶段数判断谁快。H更接近OneRec“后续商品依赖列表前缀”的组织方式，但内层仍是DiffGRM，不是OneRec原模型复现。[OneRec §3.2](https://arxiv.org/html/2502.18965v1#S3.SS2)

### 四视图噪声的必要适配

H保留每件四码的1/2/3/4遮盖深度、guided least/MSP和固定探测顺序。J不能只遮20位中的1–4位，也不建议机械让每件都始终处于相同遮盖数，因为全局逐码CPD会经过混合状态。

J首版建议：在20位上建立OCN排序，每个原始列表抽取三个不同的遮盖数量（从1–19均匀无放回抽样），再加入全MASK20位，共四个嵌套视图；按遮盖数量排序后复用同一OCN顺序。这样跨批覆盖所有深度，保留全MASK训练条件，平均监督码位数为`3×10+20=50`，与H的`5×(1+2+3+4)=50`相同。视图输入码位总数也均为80/列表，但注意力结构与Encoder计算不同，不能据此称完全同FLOPs。

这是本项目的列表适配提案，尚未验收或证明最优，不是声称作者已实现的方案。J0/J1共享相同随机遮盖深度和取数顺序。原式20个完整OCN视图可留作后续独立消融，首轮不把视图数同时扩大5倍。

J按每视图masked CE平均，再平均视图和列表；H按每件每视图masked CE平均，再平均视图、五件和列表。两边都保留per_view原则，不将H的五份损失直接相加导致学习率实质放大五倍。记录实际监督位置数。

## 5. 交替联合训练如何保留

- R阶段：冻结码本和Mixer，更新Encoder、Decoder、SID embedding、item_mlp及新增位置参数，使用当前确定性SID目录。
- T阶段：冻结推荐器参数，通过DIGER-ST推荐损失、重构/均衡/anchor更新码本，Mixer组同时更新Mixer。不能用no_grad包住整个推荐器，否则码本收不到推荐梯度。
- 尽量保留旧随机机制：每个T minibatch对历史和完整五件目标各调用一次分配，得到`history_st[B,50,4,256]`和`target_st[B,5,4,256]`。H的前缀复用该次`target_st[:,:j]`，不每步重采Gumbel，不detach前缀。T阶段带噪hard分配可能不同于目录SID，不能说它始终使用固定hard SID。
- 辅助损失对该列表批次目标的唯一商品集合只计算一次，不因H拆五步重复加五份。新数据仍保存item ID，batch中按当前版本查SID，不把SID永久写死。
- 每次T结束刷新全10728目录SID、反向多值映射、碰撞统计及合法性索引。R/T切换、checkpoint加载必须正确失效缓存。
- 沿用BF16/OCN修复：teacher探测使用no_grad且关闭autocast cache，结束恢复模块模式；验收实际权重变化和优化器step，不能只看loss或“有一个梯度非零”。零输出Mixer第一步内部Q/K/V可为零，输出投影应先获得更新。

### 建议预算：继承交替比例，按列表数据规模重算

旧05长期35R/60T来自Beauty继续训练，不能照抄到70.9万列表。建议有效batch统一为**1024条列表**，初始可用microbatch16、累积64；后续profile仅调整microbatch/累积保持有效batch。尾批按实际列表数归一化，不能把小尾批当满batch。

每R轮为`ceil(709443/1024)=693`次更新。保留旧每T阶段约覆盖训练样本5.8%的比例，设每T阶段40次更新（40960条列表），而不是旧的6次。

```text
5个R epoch共同暖身
  → 10轮 [40次T更新 + 3个R epoch]
总计：35个R epoch / 24,255次R更新 / 400次T更新
```

这是待短验收后冻结的首轮预算提案，不是已证实的收敛预算。可把第11个R epoch作为统一检查点；完整35轮调度时钟须从一开始声明，不能在中途悄悄重设退火终点。若基线仍明显欠拟合，不能据此否定交互；追加预算需要对比较双方一致并另行明确。

J和H分别完成5R共同暖身后再复制给各自±Mixer组，节省重复计算。共享PSE在暖身中冻结。复制包含权重、R优化器动量、scheduler、RNG和数据顺序；T优化器从空状态开始。R/T切换不重建优化器。500步学习率warmup只发生在最初R更新，不能fork后再warmup；5R暖身与500步LR warmup是两件事。Gumbel调度仅随400次T更新计数。

## 6. 解码、商品消歧和指标

### 共同搜索设置

首轮建议验证与测试均使用**全列表beam32**，四组一致，主输出为最高分的一份五件列表。这里的beam不是原单商品候选数：J在20位上维护32条列表路径；H在整个五件生成过程中始终维护32条全局路径，不能每条外层路径再保留32条内层路径形成32²却仍称同预算。路径分数累计20个码的对数分数；同列表不同填码顺序的重复路径按max-path去重，不按路径数量额外加分。

在同一验证选出的checkpoint上，预先安排固定验证子集的beam256敏感性检查，不重训、不重选best。若只有beam32收益、beam256收益消失，结论应限定为较窄搜索预算下有效。若profile后决定把256作为主协议，应在正式运行前同时修改四组验证和测试规则，不沿用旧val32/test256的不一致设置。

### 必须替换原单目标评价假设

旧`evaluator.py:58`的单目标Recall/IDCG=1不适用于五个相关商品；旧通过标签SID倒推item的路径也会丢失碰撞下的真实ID。新主评价直接用数据中的`target_item_ids[5]`。

令真实目标集合G含五个不同item，输出p1…p5，`rel_r=1[p_r属于G且尚未在输出中出现]`：

- Recall@5 = 命中的不同目标商品数 / 5。
- HR@5 = 是否至少命中一件。
- NDCG@5 = `sum(rel_r/log2(r+1)) / sum(r=1..5)(1/log2(r+1))`。

主选模指标固定为验证集item-level NDCG@5，平局选更早checkpoint。报告Recall@5、HR@5、有效五件输出率、重复率、非法率、延迟。NDCG检查未来五件相关集合在推荐列表中的排序，不要求预测第r件恰好等于真实第r件；如需检查消费顺序，另报逐位置命中，不混称NDCG。

默认在R5及每个3R周期结束使用同一完整验证集选模。训练/快速诊断用的固定小子集不能替代最终全验证集选模。固定R35检查点同时报告，避免只比较各自最幸运的一轮。

### 目录合法性与碰撞

- 所有10728商品可参与，**不屏蔽历史出现过的商品**，因为真实目标允许重复观看。只约束当前五件输出内部互异。
- CPD可能先填任意码位，应按已确定坐标筛选合法商品，不能只做从左到右前缀树。
- 保存SID→item bucket，多item碰撞不能被单值dict覆盖。首轮统一以当前PSE重构误差升序、原始item ID作tie-break，在最终列表位置顺序中选择未出现的商品；不使用真实目标或测试流行度消歧。
- 不同完成顺序不能改变最终消歧规则。完成SID相同的多个位置，仅在bucket有足够不同item时才可能合法，不机械把相同SID等同为相同item。
- 每次SID刷新记录碰撞率及其变化。一个SID命中不能给bucket内所有商品计命中。缺项用PAD计miss并报完成率，删除旧beam不足时重复最后候选凑数的逻辑。

### 保留NDCG@50的独立观察入口

从同一次beam固定最多32份完整五件候选列表，先按完整列表路径分数排序，再按“列表名次优先、列表内位置其次”展开，按真实item去重保留首次，截取Top50。不足50不得重复补齐，应报告覆盖率。

用原来的五件真实目标计算聚合后的Recall/NDCG@10/20/50，明确命名为**多列表候选聚合指标**。主NDCG@5仍只评价best一份列表，不与聚合Top5混淆。生成和聚合规则在正式运行前锁定，不根据测试结果改变。

## 7. 实施顺序与验收

| 顺序 | 工作 | 通过标准 |
|---|---|---|
| 1 | 共用商品表示、PSE资产和列表数据适配 | fit范围/版本/hash明确；PAD不参与拟合；每item四码；碰撞审计；不引入留出行为 |
| 2 | 先实现H0，再H1 | K=1确定性路径与旧实现一致；teacher forcing只见前缀；生成不读取target；5步一次更新 |
| 3 | 实现J0/J1 | 20位与四码本正确映射；五商品位置可区分；全MASK及各深度训练覆盖；不把n_digit改20 |
| 4 | 共用item级指标与beam | 手工小目录穷举核对；多相关NDCG；碰撞/去重/不足K；历史重复可推荐 |
| 5 | R/T小验收与断点恢复 | R仅推荐器变、T仅码本/Mixer变；梯度链路、Adam步数、SID刷新、缓存失效、恢复后一致 |
| 6 | 后续授权后短GPU验收/profile | BF16真实路径通过；四组有效batch一致；测得吞吐、显存、全验证搜索成本后锁定资源预算 |
| 7 | seed2024四格探索 | 同预算、同随机取数、统一验证选模；记录固定步与best两种结果；不只延长表现好的一组 |
| 8 | 有值得继续的信号后补2025/2026 | 三个配对seed，共12个正式模型；按冻结规则统一最终测试 |

当前工程以单模型单GPU为已验证路径。未来可四组各1张H100并行；若有8张，稳定协议后可同时运行两个seed×四组，不把未经验证的8卡DDP当默认。本轮没有申请任何GPU，也没有承诺未测量的训练时长或费用。

结果同时报告配对seed增益、均值/标准差和按用户重采样的配对置信区间；保留样本平均主结果，并补用户平均、含冷启动商品/全部已见商品分组。用户bootstrap不能代替多seed。

若Mixer只在一个架构、一个seed或一种beam宽度有效，应明确限制，不写成稳定整体提升。若有稳定收益，再增加同参数量但无跨码字交互的self-only控制，以区分交互机制与额外参数容量；之后才考虑grid/loop。

# 下一轮最小实验：先检验session信息，再判断grid与loop

> 2026-10-24更新：以下为旧概率路由/四臂候选计划，当前执行以[阶段08说明](../../../experiments/08_session_codeword/README.md)及其JSON为准：三臂、直接残差、统一验证beam256。主比较是固定R35的NDCG@10；另以`0.8*NDCG@10+0.2*HR@10`封存best，候选包含R0，属于次要结果。下文旧“按NDCG选best”不适用于当前实现。

日期：2026-10-23。**这是一份待执行计划，不是GPU授权，也没有启动其中任何训练。**

## 1. 先回答的一个问题

**在保留05离散SID、共同起点及交替联合训练时，让真实64维码字在当前历史中交互，是否比同样路由结构但只看单商品，更能改善下一商品推荐？**

该问题比“grid+loop有没有涨点”更值得先验证：只有先证明跨历史条件有用，才值得继续优化连接图与迭代深度。它也区分了“新增语义旁路/参数有用”与“session交互有用”。

主假设不是缩短生成步数。新分支仍接原生4步DiffGRM；质量收益要同时接受额外延迟的检查。

## 2. 第一轮：4臂，一个seed，不一次堆全部方法

| 臂 | 原05全局Full Mixer及T更新 | 新历史分支 | 回答的问题 |
|---|---|---|---|
| B0 | 开启 | 无 | 当前统一实现/评估口径下的05 Full Joint参照 |
| B1 | 同B0 | 与B3同两次MHA，码位轴正常交互，时间轴只看当前位置自身，r=1 | 保留语义旁路、参数和投影深度，关闭跨商品可见性 |
| B2 | 同B0 | 展平L×4完整交互，r=1 | 简单session方案参照；与B3比较连接模式整体的质量/成本 |
| B3，首选 | 同B0 | 先码位轴、后时间轴，r=1 | B3−B1：session信息；B3对B2：分轴模式的质量/成本取舍 |

B1/B2/B3共用F的参数形状、初始化、位置/book标签、FFN与读出头；两个轴共用同一MHA，新增参数均41,152。**B3−B1只改时间轴可见性**，两者投影次数和密集矩阵形状相同。B2只有一次full MHA；它与B3的差含连接模式和投影深度，不能声称是纯单因素的grid优势，必须连同实测成本报告。原型mode=`no_context`才是正式B1；只有一次MHA的`item`仅作CPU参考，不是旧07结果或其256维模块。

四臂是当前目标的最小实用集合：只做B0/B3可以初探整体效果，但无法判断是session、旁路还是grid的作用。预算不足时明确降级为“机制未识别的探索”，不要用两组结果回答四组问题。

## 3. 共同起点和训练配方

共同资产以 [05long配置](../../../configs/05_crosspse_joint/long/mixer_long_seed2024.json) 和 [历史完整报告](../../../experiments/05_crosspse_joint/long_mixer_factorial/REPORT.md) 为身份依据：

- 推荐器：`external/DiffGRM/saved/AmazonReviews2014_Aug-28-2026_19-01-02/pytorch_model.bin`，不是07 refined warm-start或05某臂最终权重。
- 有效码本E0：05短四组共同initial的 `crossed_codebooks.npy`，文件SHA256 `ce4f0747875640f8b1c0e4046feb328a904d7beb96f3940f871f923f5f79b17c`；数组SHA256 `ed40b23bbacd78824ee6f9da5c7fcba4b5e4b2920b9890d8bf7e498635eed5b1`；canonical SID数组SHA256 `ee955d3b79e69e4c9c96fce6b7f4f8f46aad17eeedd0f55d04298078b24967ea`。
- 复用同一商品顺序、OPQ/slots/anchor与Beauty leave-one-out数据。`train_sliding=true,min_hist_len=2,max_hist_len=50`。不要换06前缀协议。
- 四臂全局Mixer均为Full、4heads、输出投影0、固定残差1，从同一E0重基；不是复用已经训练后的Full输出再叠一次。
- 新F读出头0，eta0.1/gamma1，dropout0、FFN128、r1；B1/B2/B3的F逐tensor相等，共有参数逐tensor相等，初始SID/logits/验证指标一致。F初始化用隔离RNG，不消耗原推荐器随机流。
- 新建相同原推荐器/Tokenizer优化器初态与调度，不从历史last接Adam动量。新F归R，LR1e-3/weight_decay0，沿用R调度；C归T LR1e-5、全局Mixer归T LR1e-4/weight_decay1e-4。

本轮只核对了上述历史配置/证据，未重新加载大权重或验证远端资产可用性；实际实施前需独立校验全部输入字节与共有tensor。

| 设置 | 四臂统一值 |
|---|---|
| 首轮seed | 2024；同一预训练起点的下游训练seed |
| R节奏 | 先5R，再10×(T阶段+3R)，共35R/3640更新 |
| T节奏 | 每阶段96 microbatch，累积16，6更新；共60T |
| batch | train64、eval8、累积16；尾部真实窗口归一化 |
| 推荐器 | embedding256、Encoder1层、Decoder4层、4heads、inner1024；原dropout0.1 |
| 原损失 | label smoothing0.2，推荐/重构1，balance/anchor各0.01，SIA0 |
| 温度及Gumbel | 距离0.1；原独立history/target流，累计60次T的cosine1→0.2；新残差无额外噪声 |
| R学习率 | 500次warmup后cosine，累计3640；T不推进R scheduler |
| 精度 | 继承已修复的BF16 R、FP32 T及OCN teacher缓存/混合train-eval修复；新距离/归一化/softmax/概率相减及残差读出显式FP32 |

开始训练后B1–B3的新F从第一轮R就学习，因此**不再要求前5轮loss与B0完全相同**。需要相同的是初始共有状态和预设数据/噪声流。新增参数也会影响全局梯度裁剪，这属于新方法整体干预，应记录而非声称所有更新逐步完全一致。

## 4. 指标、选模、候选处理提前固定

第一轮只用同一完整验证集，不读取测试指标调参。四臂使用同一native confidence/4步协议，`val_beam_act=val_beam_max=256`、`topk=[5,10]`、`top_k_final=10`，保持相同目录过滤、去重与不足候选回填，并额外报告回填/无效/唯一候选比例。

beam是验证/推理设置，不是反向训练的“训练beam”。从旧05验证32改成统一256后，不能把旧表数字当新B0；必须在新协议中重跑参照。小beam效应留作后续搜索因子，不在本轮边跑边选择。

**主要比较：固定R35、同训练预算的验证NDCG@10。** 同时报告HR@10作覆盖护栏，@5作描述。不用每臂最高分混成固定预算比较。初始及R5/10/15/20/25/30/35验证；另按NDCG@10、平局最早，封存best供将来测试，作为选模程序的次要分析，不替代R35。

当前主要指标为SID-level。必须同步报每臂目录碰撞率、目标SID碰撞子集结果，以及每用户候选合法/去重覆盖；否则更易命中一个对应多个商品的SID可能产生误导。若加item-level，预先固定SID到多个item的展开与排序规则（仅训练数据频次/固定ID打破平局），统一截断，再与SID级分别呈现；不能拿05/新方案的SID分数直接和06 SASRec item分数排序。

**@50不是本轮必备。** 现有`top_k_final=10`不能直接给出有意义的@50。若后续采用，四臂必须同时配置`topk`和`top_k_final≥50`、有效beam≥50，逐用户核对前50合法唯一SID、重复回填与返回长度，再冻结协议；不要为满足50个结果只复制最后一个候选。合法不足时如实报告覆盖，或另立统一扩大搜索预算的比较。

## 5. 事先的继续/停止标准

以下1%、0.5%、20%是拟定的**探索阈值**，不是显著性结论或历史已确认标准；正式运行前固定，不能看到结果后改：

1. 首选B3相对B0的R35 NDCG@10相对增幅≥1%，且相对同深度B1也≥1%；HR@10相对下降不超过0.5%。满足才把结果称为“值得复验的session信号”。例如B1单独改善但B3不再改善，结论应是旁路/容量有效，尚无session作用证据。若仅B2改善，把它称为备选结构信号，补与full同为1次MHA、只看同商品的item控制后，才能隔离full的session作用；不能用不同深度B2−B1作纯上下文效应。
2. 配对记录每用户命中/排名变化，做用户重采样区间供描述；这不替代独立seed。效应小于阈值、方向混合或集中在碰撞子集，先报告不确定，不追加模块追涨。
3. 端到端推理固定batch、beam、输入长度；从H→router→Encoder→beam→目录输出，报告p50/p95、吞吐、峰值显存与分段耗时。排除`trainer.evaluate`附带的full-mask/greedy标签诊断，避免把评估开销当请求延迟。若质量信号相当，优先低成本结构；超过B0延迟20%的方案先标为成本不达标，不称速度改进。CPU单独router计时不用于判这个门槛。
4. 若B2/B3均无足够信号，先看路由是否真的学动：读出梯度、PH−P0、残差比例、T回C梯度、SID漂移。路径正常且结果仍持平，则本设置下不支持继续堆loop；路径数值饱和只能说明本配方未激活假设，不能断言所有session编码无效。

## 6. 第二轮才分解loop与共享

仅第一轮出现可复验信号后，对选中连接模式保持输入/输出/损失不变，比较：

| 对照 | 含义 |
|---|---|
| r1单块 | 第一轮已完成的参照 |
| r2共享同一块 | 判断多轮状态修正的整体收益；相对r1包含更多计算 |
| 两块不共享，深度2 | 与r2近似相同计算、参数更多；区分参数共享和单纯更深 |

不因r2超过r1就宣称“循环共享有效”；要看其与同深度不共享以及实测成本的取舍。随后在seed2025/2026复验封存后的B0、B1及胜出方案，至少同时报告三seed均值、标准差、逐seed方向和配对差。它仍是相同已学习E0/推荐器上的下游seed复验，不是预训练全链路独立重复。

若要声称物理码本联合适配是关键，进一步增加同一新路由但冻结Tokenizer的对照；若要声称优于普通历史加深，应增加同预算普通item历史层。这两项是**论证机制/写论文所需扩展**，不是第一轮4臂已能回答的结论。

测试集仅在结构、超参、seed与选模全部封存后一次性评估胜出方案及对应对照；不因测试小增益再回头改seed、beam或k。

## 7. 后续资源：估算，不视作申请

历史05long的 `formal/*/TRAIN_COMPLETE.json` 各phase实耗求和：Full Joint约1.7203小时、No Mixer Joint约1.4681小时/单H100；不含全部验证、保存、排队、分配空转。历史四臂全Goal含失败/验收/评估共9.8747 GPU小时，不能把它当新四臂精确成本。

本计划第一轮优先**4个独立单卡任务并行，每臂1张H100**；不为小模型使用8卡DDP。只有2张时分两批，保持实验内容不变。先预留最多0.5 GPU小时做单卡真实R/T、恢复和测速，再根据新模块实际单步/验证耗时核算是否运行四臂。

粗略规划为首轮四臂合计**12–16 GPU小时**，对应4卡约3–4小时墙钟加准备/排队；这只是预留区间，尚无H100新模块测量，不能保证足够。若新增全K路由使内存/反向明显变慢，应先给出测算，不擅自增加预算或缩减基线。loop与多seed另立增量预算，不包含在此区间中。

CPU参数/内存近似及微基准见 [DESIGN.md](DESIGN.md#9-资源测量与局限)。GPU门必须覆盖：BF16/OCN所有应更新参数梯度、T的F冻结但回C、R/T状态恢复、Gumbel/数据流配对、同初态、不同batch padding、SID和checkpoint绑定、全样本beam口径、实际资源释放。还需拆分原`prepare_joint_batch`对target的无条件要求，验证只输入H即可真实generate，且移除/置换target不影响encoder_hidden与预测。CPU原型没有代替这些门。

## 8. 和学长确认的最多3个问题

1. 我准备先保持目标商品的全局SID，只让历史中的64维码字结合当前session做条件路由；这符合你说的session-wise吗，还是你希望目标商品的SID本身也随历史改变？
2. 首轮按“推荐器阶段学习session模块，Tokenizer阶段冻结它、让推荐梯度穿过它更新码本”推进，保留原来的交替联合训练；你希望新交互模块也只归Tokenizer阶段吗？
3. 我先把目标定为在固定搜索预算下获得稳定推荐收益，同时测额外时延，暂不减少原生生成步数。这样的优先级是否符合你现在最想验证的问题？

这三点是研究定位的确认；当前设计已按前述假设闭合，不需要停在这些问题上才能完成本轮报告与CPU验证。

# Session-wise 首版实现审查：历史码字交互残差

日期：2026-10-24。范围：原始论文核对、方案取舍和实验解释边界；本文没有训练结果。本审查仅新增本文件，不修改旧设计、生产代码或历史实验记录，不运行GPU。

已检查工作目录及父目录的 `AGENTS.md`，以及 `docs` 下的同名文件，本次未发现适用文件。参数血缘核对了当前 [05长期配置](../../../configs/05_crosspse_joint/long/mixer_long_seed2024.json)、[2026-10-23设计](DESIGN.md) 和 [当日实验计划](EXPERIMENT_PLAN.md)。

## 1. 建议实现什么，以及它回答什么

建议首版保留05的全局规范SID、Full Mixer、交替联合训练和原DiffGRM解码。在历史商品的四个码位被压成一个item向量之前，读取真实64维码字，进行一轮“码位轴→历史时间轴”交互，再通过零初始化线性层产生256维残差，加入原SID embedding。

**需要验证的问题是：相同分支与参数下，允许码字读取其他历史商品，是否比只看当前商品更有效？** 原历史Encoder已经建模跨商品关系，因此这里的假设是“保留码位结构和物理码字信息的较早交互仍有额外价值”，不是首次把历史放进推荐器。

这属于**session条件的历史表示**。同一目录版本中，目标商品仍使用 `SID(i)`，不是 `SID(i|H)`。“session”继续指旧任务中可见的历史前缀，不按时间间隔重新切会话，也不改成预测整段未来session。每个Tokenizer阶段结束后，全局SID仍可以随共享码本统一刷新；“规范身份”不等于永久冻结Tokenizer。

## 2. 与旧草案的关系

| 项目 | 2026-10-23草案 | 本次建议 |
|---|---|---|
| 交互后的读出 | 修正整本中心距离logits，计算 `eta*(PH-P0)@W` | `Linear_zero(64→256)` 直接生成历史残差 |
| 双轴参数 | 两轴共享MHA，以便与full参照对齐参数量 | 两个独立MHA；码位与时间是不同关系，先不额外强制共享 |
| 首轮对照 | baseline、no_context、full、axial | baseline、no_context、axial；只先判断跨历史可见性 |
| loop | 条件性后续实验 | 同样推后，不与首版一起引入 |

简化动机是去掉额外的全K概率计算、温度和概率差幅度等耦合因素，更直接检查历史交互。它不保证更好，也不等于旧概率路由的数学近似。本版没有重新分配各中心的条件概率，宜称“历史码字交互残差”，不沿用“已经实现条件化量化”的说法。

旧草案 `eta=0.1` 只是当时的探索假设，没有真实训练支持；新 `scale=1` 也只是起步选择。旧CPU微基准、参数量和通过项不能直接当作本版两套MHA与新读出的验收或速度结果，必须随新实现重新检查。

## 3. 哪些文献真正支持了设计，支持到哪里

本轮没有完整复现以下任何论文。DiffGRM是既有代码基础；其他工作只提供机制或问题定位，不能将其公开涨点当作本项目收益预测。

| 原始来源与重点阅读处 | 本次可用的依据 | 不能据此宣称 |
|---|---|---|
| [DiffGRM v1](https://arxiv.org/html/2510.21805v1)，§3.1–3.4 | PSE使用OPQ分块码；历史各SID embedding先合并成item向量，之后进入历史Encoder；目标采用masked离散解码。适合保留原推荐任务、解码与目录接口。 | 原论文已经验证05交替更新，或验证本次64维历史分支；“4位SID”也不能直接等同于所有配置都只需4次完整模型调用。 |
| [ActionPiece v3](https://arxiv.org/html/2502.13581v3)，§3.2、§3.3 | 跨相邻行为的特征模式可以进入tokenization；历史与下一商品分别处理。这支持研究上下文进入较早编码环节的动机。 | 它实现了本次注意力残差，或每个请求都更新整张码本。它使用合并词表及SPR，推理集成还有额外计算。 |
| [Pctx v1](https://arxiv.org/html/2510.21276v1)，§2.2–2.3 | 上下文侧面与内容融合后形成有限多SID，并在生成后归并到商品。它展示了真正改变上下文身份需要编码与落地目录一起设计。 | 当前单规范SID方案就是Pctx；将其AR流程迁移到DiffGRM不需要新实现；它是任意Decoder的通用Encoder。 |
| [Axial Attention v1](https://arxiv.org/html/1912.12180v1)，§3.1、§3.2 | 将其他轴临时并入batch，沿单轴做标准attention，再恢复形状；多轴串联传播信息。可借鉴到 `[L,4]`。 | 图像实验已经证明推荐有效；两轴块等价于full attention；减少注意力配对就等于端到端同比提速。 |
| [Universal Transformers v3](https://arxiv.org/html/1807.03819v3)，§2.1–2.2 | loop指沿计算深度反复更新同一组状态，可共享参数；动态停止是额外机制。只作为后续轮数研究参考。 | 反复计算必然降低时延；首版需要ACT；只比较一轮与两轮就能识别参数共享的价值。 |

按当前实现需求，先重读DiffGRM接口与Axial §3.1；ActionPiece用于理解上下文编码的动机；Pctx用于明确本版没有做的身份变化。Universal Transformers可等单轮有信号后再细读。本次采用的是PyTorch标准MHA及原有项目部件，不整包迁入图像模型或另一套推荐器。

## 4. 建议的完整前向路径

记共享有效物理码本为 `Cbar=FullMixer(C)`，形状 `[4,256,64]`；推荐器自己的SID表为 `W[4,256,256]`。二者不是同一张表。历史分配为 `A[B,L,4,256]`，其中R/推理用hard分配，T沿用05的hard-forward/soft-backward路径。

```text
历史 H：训练沿旧早期前缀扩样；验证/测试取目标前最近50件
    ├─ 原分配 A → A@W ───────────────────────────────────────┐
    └─ A@Cbar → [B,L,4,64] → 时间位置/码位身份                │
             → 码位轴MHA → 时间轴MHA → FFN                  │
             → LN → 零初始化Linear(64→256) → scale×残差 ────┤
                                                           ↓
                           相加 → 原item_mlp → 原历史Encoder
                                → 原DiffGRM解码 → 规范SID目录
```

建议使用Pre-LN及块内残差；两轴各自使用独立MHA与LayerNorm。码位轴处理 `[B*L,4,64]`；时间轴处理 `[B*4,L,64]`；恢复后用一个 `64→128→64` FFN。历史每个位置仍保留4个输出码位，最后逐码位映射到256维，而非提前池化掉码位结构。

时间轴首版沿用因果可见性，令位置t只读取不晚于t的历史；同一商品四码位可互看。它是保持前缀语义的工程选择，不是说最后一步预测中对完整可见历史使用双向编码必然泄漏。必须屏蔽PAD的key与输出，处理全PAD/无有效key情况，并确保不同样本不会因reshape混进同一注意力序列。

零初始化最后读出层的权重与bias，使初始残差为零；固定scale为1，不再额外设置一个同时为零的可学习门。初态与baseline共有路径应一致。**第一次R反向中，交互核心可能因零读出而没有梯度，这是预期；应在读出完成一次更新后再检验核心梯度。** 这与梯度断链是两个不同问题。

新增分支只计算一次历史表示，供后续OCN视图或beam使用，不随每个候选重复计算。本次保留项目现有原生四位解码调度，不减少生成步数，也不把新增历史模块称为时延优化。

当前数据构造需准确区分：设用户序列长度为 `Luser`，训练按 `t=2..min(Luser−3,50)` 生成早期前缀样本，并非把长序列的所有位置都展开成滑动窗口；验证和测试分别截取各自目标之前最近最多50件商品。首版沿用此协议，不把“最多50”笼统解释为训练、验证和测试都取最近50件。

## 5. 参数的来源与可信度

| 设置 | 首版值 | 来源/为什么这样设 |
|---|---|---|
| 物理码位/中心/维度 | 4 / 256 / 64 | 继承05资产；不是本轮调参 |
| 输出残差维度 | 256 | 对齐原推荐器SID embedding，以保留原item_mlp接口 |
| 历史样本 | 训练 `t=2..min(Luser−3,50)` 早期前缀扩样；验证/测试取各自目标前最近最多50件 | 继承旧数据构造；训练并非长序列全滑窗 |
| 交互轮数 | 1 | 先识别上下文是否有用；不是文献证明的最优深度 |
| 双轴关系 | 先码位、后时间；两套独立MHA | Axial机制启发；具体顺序和独立参数是本项目选择 |
| d_model / heads | 64 / 4，每头16 | 匹配物理码字；复用熟悉的4头规模，但最优头数未验证 |
| FFN hidden | 128 | 小规模2倍扩展，控制容量；没有论文提供本项目最优值 |
| 新分支dropout | 0 | 降低首轮新增随机因素；不改变原推荐器既有dropout |
| 末层/scale | 零初始化 / 1 | 保持初态函数一致；训练后残差幅度仍须测量 |
| 全局Full Mixer | 三臂统一开启 | 保持05血缘并隔离新交互；不是重新论证Full优于无Mixer |
| R/T节奏 | 35R、60次T更新 | 继承05长期配方：5R，再10轮(T+3R)；不是原论文推荐设置 |
| 新F的优化器 | 归R；默认沿R的LR和调度 | 当前假设：请求内表示随推荐器学习；不声称归R优于归T |

四头、FFN128、dropout0和scale1都应标为预先固定的起步值。旧35R/60T预算只提供统一比较长度，不保证新分支已经充分收敛。不要在首轮一边看验证分数一边同时调头数、轮数、残差幅度和beam。

## 6. 怎样保留交替联合训练

| 阶段 | 更新 | 保持冻结 | 必须保留的计算路径 |
|---|---|---|---|
| R | 推荐器、W、新F及64→256读出 | C和全局Full Mixer | hard分配，冻结有效码本可缓存 |
| T | C和全局Full Mixer | 推荐器、W、新F参数 | F输入梯度仍存在；live Cbar经 `A@Cbar→F→残差` 回传，原ST及目标监督路径继续保留 |
| 验证/生成 | 无 | 全部 | 使用checkpoint绑定的码本和规范目录；只有可见历史进入新分支 |

“冻结F参数”不等于把F放进 `no_grad` 或detach其输入。每T后按全局码本统一刷新SID、反向映射与cache；保存恢复需包含F、共享码本、目录身份和原R/T状态。新模块构造应隔离随机数流，不能因为多初始化几个tensor改变三臂共有模型起点或数据顺序。

原joint接口对target字段的依赖需要按本次代码审计拆成历史准备与监督准备。生成时去掉或置换target，不应改变encoder_hidden和预测。标签可以用于损失，不能流入新的历史分支。

## 7. 三臂实验与可解释的判据

| 臂 | 结构 | 解释 |
|---|---|---|
| baseline | 当前统一实现下的05 Full Joint，无新F | 测新增方案的整体收益与成本 |
| no_context | 与axial完全相同的两套MHA、FFN、位置/码位标签和读出；时间轴仅看自身 | 控制额外容量、码字语义旁路和投影深度 |
| axial | 只将时间轴开放为合法历史前缀 | 与no_context的差主要检验跨历史可见性 |

no_context仍执行两次MHA，不能删掉时间模块或改用较小网络。即使掩码不同，实际内核成本仍可能不同，应实测而非宣称成本严格相等。三臂从相同E0、推荐器、原优化器初态和数据协议起步；两个新增分支共有参数也逐tensor一致。

no_context的时间轴每个query只有一个可见key，softmax恒为1，因此这一轴的Q/K投影可能合法地获得零梯度。不能把“所有参数都非零梯度”作为统一通过条件；应分别检查图连通、梯度有限、V/O及码位轴更新，并在axial检查跨历史作用。

第一seed只在同一完整验证集探索。建议固定R35的SID-level NDCG@10为主、HR@10为护栏，统一beam256、原生解码、目录过滤、去重与有效候选长度；分开报告各自best，不将其冒充固定预算比较。当前旧05配置的验证beam是32，因此旧05长期结果不是本轮baseline。旧05早期长期、共享起点短对照及07也不能替代新的no_context或axial。

可沿用上一版预先提出的探索门槛：axial对baseline及no_context的NDCG@10均相对提升至少1%，HR@10相对降幅不超过0.5%，相同batch/beam下端到端延迟增幅不超过20%，再投入后续复验。**这些是暂定取舍线，不是统计显著性标准；必须在真实运行前冻结。** 同时保留每用户配对变化及区间，检查碰撞子集、无效SID、唯一候选覆盖和回填比例。

- no_context有增益，axial没有额外改善：支持语义旁路/容量可能有用，尚不支持session交互。
- axial同时超过两组且成本可接受：得到值得多seed复验的信号，不直接宣布稳定有效。
- 三组接近：先确认新分支确实学动及R/T梯度路径正常；路径正常仍持平，就暂不堆loop追涨。
- 只有SID级改善或改善集中在碰撞样本：先排查身份/指标变化，不能直接解释为真实商品推荐变好。

有信号后，对预先封存的同一配置补seed2025/2026，报告逐seed差值、均值和波动；这仍是相同预训练起点的下游复验。最终测试在方案封存后进行。若要声称物理码本联合适配至关重要，再加冻结Tokenizer；若要声称优于普通历史加深，再加等预算item历史层。首轮三臂没有回答这两个更强的问题。

## 8. 最需要保留的风险判断

1. **OPQ几何不天然对齐。** 不同码位的64维来自不同子空间；book身份与可学习投影是否足够，需要验证。独立的时间/码位MHA并没有自动消除这个问题。
2. **可能重复原历史Encoder。** 额外交互可能只是增加容量；与no_context的比较回答跨历史可见性，仍不等于证明胜过普通item级历史模块。
3. **连续旁路不等于量化更好。** T新增了一条直接利用C的连续梯度路径。涨点可能来自表示旁路，而非目标SID分配改善；重构/anchor和SID漂移仍要观察。
4. **零初态不保证后续幅度。** 记录有效位置的残差范数/原AW范数比、读出与MHA梯度、T回C梯度。scale1不是训练后的幅度上界。
5. **不能预支速度收益。** 首版增加历史计算，目标仍原生解码。配对数减少仅与full交互相比，不能用来声称比无分支baseline更快。
